SOC triage & identity workflow lab

A personal engineering lab connecting Python APIs, PostgreSQL, security triage, and employee identity workflows.

The problem

An alert needs enough context for someone to decide what to do next. Identity records introduce another challenge: an employee can return with a new identity-provider account while an application still points to the old record. This lab uses fictional retail scenarios to explore those failures.

What the lab contains

  • FastAPI services for normalizing alerts, collecting evidence, and recording triage decisions.
  • PostgreSQL persistence, migrations, and a tested backup/restore workflow.
  • n8n alert workflows, approval-gated response actions, and a Svelte interface.
  • Synthetic onboarding and rehire scenarios, plus an optional Keycloak/OIDC lab.

Verification

The October 8, 2026 validation run exercised 42 alert cases, 10 identity scenarios, and PostgreSQL backup/restore. These are controlled lab checks; they do not measure performance on an organization's live traffic.

Current limits and next work

The default path uses deterministic mock AI. Live integrations and broader API authentication and authorization remain in progress. The project is an AI-assisted personal build and learning environment, separate from employer systems, and does not claim production readiness or PCI certification.

Source is currently private. Public detection and automation projects are available on GitHub.
